# Lane R5 — brief

The whole brief for the Settings lane of the redesign (`factory/REDESIGN.md`). The launch prompt is the block below. It
works as a cloud session (environment `Shifty`, starts from `main`) and as a local session on Bill's Mac in its own git
worktree.

**Before launch, the orchestrator fills in the D13 line** (acceptance point 4) with Bill's answer. Until Bill answers, it
stays as written: the Accent row is kept.

```
LANE R5 — Settings: all settings pages, account and data, install guide · app SHIFTY (mafiabossbill/shifty)

AGENT: frontend-engineer. You are this agent for the whole session: read `.claude/agents/frontend-engineer.md` first and
work under that contract. You are one lane of a larger redesign. Four other lanes (R1 Home, R2 Sessions, R3 Insights,
R4 Companion) run at the same time on other files. Do not start other sessions.

START: the default branch `main` is PRODUCTION. Never base work on it and never open a PR into it. Your branch must start
from the integration branch `redesign`:
- Cloud session (you began on `main` or on a branch cut from it): `git fetch origin redesign`, keep your branch name and
  `git reset --hard origin/redesign` before any work.
- Local session in its own git worktree, on a branch already cut from `redesign`: `git fetch origin redesign`, then
  `git merge-base --is-ancestor origin/redesign HEAD`. If that fails and you have no commits of your own yet,
  `git reset --hard origin/redesign`.
Either way `factory/handoffs/redesign-r0.md` must exist once you are on it. If it does not, the foundation is not merged
yet: stop and say so. `npm ci` first. At the end open a PR with base branch `redesign`. Never merge, force-push to a shared
branch, or deploy.

  anywhere else, the main checkout included.

  generated data.
- Chromium: `export E2E_CHROMIUM_PATH="$(ls -d ~/Library/Caches/ms-playwright/chromium_headless_shell-*/*/chrome-headless-shell | tail -1)"`,
  or `npx playwright install chromium` if nothing is cached.

  `npx next dev -p 3015` · `E2E_BASE_URL=http://localhost:3015 npm run test:e2e` · `npm run design:shots -- --port 4315 --only /design/screens/settings`

In the cloud: Chromium is usually `/opt/pw-browsers/chromium`; the default ports are fine.

each screen from its plan in `factory/PRODUCT_BLUEPRINT.md` § Screens and show every state the plan lists in the gallery.

ACCEPTANCE:
1. Every file you own that carries `// design-ok-file: awaiting redesign lane R5 (settings)` is converted and the marker is
   removed. Today that is 17 files: in `src/components/settings/`: `account-settings`, `data-settings`, `demo-link`,

3. Each page follows its row in the plan's table (purpose, content 1 · 2 · 3, states, must change). The "Must change"
   column in short: the menu's group names are captions in sentence case and its rows are lines in one list per group, with
   quiet small icons, no tinted icon circles and no card per row; workday and reminder chips are toggle buttons whose
   pressed state is marked twice (surface and a check); hints sit between label and control and errors above the field

   never colour alone; install steps are a numbered list, not three boxes; the four "doesn't do" lines are a plain list;
   the import preview's four counters are `StatTile`s with no boxes; the printable report's preview is always light (it is
   paper) and its print rules stay.
4. D13, the Accent row on `/settings/appearance`: **not decided by Bill when this brief was written. Keep the row.**
   Restyle it with the rest of the page and leave it working as today (it stores the value; since R0 it colours nothing).
   Do not remove it and do not make it tint the interface (R-D5). Say in the handoff that it is still there. The saved
   value is never changed or deleted either way.
5. One solid button a page at most, as the plan's table names it (Save place inside the new-place form; Install SHIFTY only

   only in their dialogs, which keep typing the email or ERASE. Three of them are still red at rest after R0's rename
   (`account-settings`: Erase this device, Delete my account; `privacy-settings`: Delete all): make them quiet.
6. `create-workspace-form.tsx` is used by `/onboarding` (R0's page): convert it with `Field` (it still has a local label and
   a red 13px error) and keep its props. `timezone-picker.tsx` is used by the Sessions lane's timezone sheet: keep its props.
7. Gallery: `src/lib/design-gallery/settings.ts` replaces every `awaiting("R5")` with a gallery entry, and there is a page

   demo on; goal invalid, notifications blocked, limit on; pay off, on with no rate, invalid amount; no places, locating,
   location refused, form open, name missing; installed, prompt available, iOS, Android, other; no points, over 50; export
   failed, file unreadable, nothing to add, conflicts, empty month; demo, sync not set up, not signed in, signed in, upload
   waiting, another account's data, signed out with changes waiting), plus the confirm dialogs held open. Sample helpers go
   in `src/components/design/settings-samples.ts`. A state the store's public actions cannot reach (a browser capability,
   a signed-in account) is shown with an optional prop for the gallery, or listed in the handoff with the reason; it is
   not a licence to edit the store or to add a backend.
8. Behaviour unchanged: every preference saves as today; exports carry the same data; the import dry run, the location

9. `npm run check:full` green; `npm run design:check` 0 errors; every `design-ok` you add has a real reason and is listed
```
