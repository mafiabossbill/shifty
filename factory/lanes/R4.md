# Lane R4 — brief

The whole brief for the Companion lane of the redesign (`factory/REDESIGN.md`). The launch prompt is the block below. It
works as a cloud session (environment `Shifty`, starts from `main`) and as a local session on Bill's Mac in its own git
worktree.

```
LANE R4 — Companion: Mochi's screen, rewards, achievements, XP log · app SHIFTY (mafiabossbill/shifty)

AGENT: frontend-engineer. You are this agent for the whole session: read `.claude/agents/frontend-engineer.md` first and
work under that contract. You are one lane of a larger redesign. Four other lanes (R1 Home, R2 Sessions, R3 Insights,
R5 Settings) run at the same time on other files. Do not start other sessions.

START: the default branch `main` is PRODUCTION. Never base work on it and never open a PR into it. Your branch must start
from the integration branch `redesign`:
- Cloud session (you began on `main` or on a branch cut from it): `git fetch origin redesign`, keep your branch name and
  `git reset --hard origin/redesign` before any work.
- Local session in its own git worktree, on a branch already cut from `redesign`: `git fetch origin redesign`, then
  `git merge-base --is-ancestor origin/redesign HEAD`. If that fails and you have no commits of your own yet,
  `git reset --hard origin/redesign`.
Either way `factory/handoffs/redesign-r0.md` must exist once you are on it. If it does not, the foundation is not merged
yet: stop and say so. `npm ci` first. At the end open a PR with base branch `redesign`. Never merge, force-push to a shared
branch, or deploy.

ON BILL'S MAC (skip this block in the cloud):
- Work only inside your own worktree folder. Other lanes use other folders. Never switch branches, stash, reset or edit
  anywhere else, the main checkout included.
- There is no `.env` file and none is to be created. The app runs without a backend in device mode; `/?demo=1` shows
  generated data.
- Chromium: `export E2E_CHROMIUM_PATH="$(ls -d ~/Library/Caches/ms-playwright/chromium_headless_shell-*/*/chrome-headless-shell | tail -1)"`,
  or `npx playwright install chromium` if nothing is cached.
- Your ports, because other lanes run servers at the same time: dev server 3014, screenshots 4314.
  `npx next dev -p 3014` · `E2E_BASE_URL=http://localhost:3014 npm run test:e2e` · `npm run design:shots -- --port 4314 --only /design/screens/companion`
- Stop every server you started before you finish.
In the cloud: Chromium is usually `/opt/pw-browsers/chromium`; the default ports are fine.

READ FIRST, in this order: `factory/REDESIGN.md` (the plan, decisions R-D1…R-D6, ownership, the marker rule),
`factory/handoffs/redesign-r0.md` (all of it: §3 renames, §4 the mechanical edits already made in your files, §5 how to add
a gallery page, §9 asks), `factory/PRODUCT_BLUEPRINT.md` § Screens ("Rules every plan shares", then "`/companion` Companion
(R4)"), `factory/DECISIONS.md` D11 to D21, `docs/factory/docs/UI_UX_STANDARD.md` (§1 the tells, §2 order of work, then the
sections for what you build), `docs/factory/checklists/design-review.md`, `factory/SCREEN_LANES.md`, `CLAUDE.md`. Then open
`/design` in development: it shows the whole system.

GOAL: Redo the look of the Companion screen (`/companion`, with its `?tab=` tabs) from the design system lane R0 installed.
Look only (R-D1): Mochi, the wardrobe, the room, the rewards, the achievements, the XP log, every action, URL, piece of copy
and behaviour stay. Mochi's drawing keeps its own colours (R-D4); everything around the drawing follows the system. Build
the screen from its plan in `factory/PRODUCT_BLUEPRINT.md` § Screens and show every state the plan lists in the gallery.

ACCEPTANCE:
1. Every file you own that carries `// design-ok-file: awaiting redesign lane R4 (companion)` is converted and the marker is
   removed. Today that is 11 files: in `src/components/companion/`: `achievements-list`, `celebration`, `companion-hero`,
   `companion-screen`, `how-xp`, `item-grid`, `item-preview`, `level-card`, `rhythm-card`, `xp-log`; and
   `src/components/mochi/gallery.tsx`. No retired class, variant or prop is left in any converted file (handoff §3;
   `tests/design.test.ts` enforces it once a marker is gone).
2. Mochi's drawing is not restyled. `src/components/mochi/mochi.tsx`, `habitat.tsx` and `parts.ts` carry a permanent
   `design-ok-file` line with the R-D4 reason: leave that line and the drawing's colours, shapes and motion as they are.
   Do not add that exception to any other file.
3. `src/components/mochi/gallery.tsx` is not a drawing file: it is an unused pose sheet with its own colours and capital
   labels. Turn it into gallery pages under `src/app/design/screens/companion/` or delete it; say which in the handoff.
4. No primary action. A tap on an unlocked item wears it at once; Rename is a ghost icon button with a label.
5. Must change (from the plan): level and name pills over the picture become text under it. Orange "celebrate" tints,
   tinted XP chips and glow go: XP is "+20 XP" in plain tabular text. The level shows XP as a `ProgressBar` with the words
   "340 / 500 XP · 160 XP to level 8". The celebration is a quiet notice (Mochi small, the achievement's name, Dismiss);
   nothing bounces outside the drawing itself.
6. Pattern (from the plan): the habitat is the one picture and its own box. Level and rhythm are figures with no box. Items
   are a grid of tiles, each with one border; the worn item is marked twice (a darker border and "Wearing" with a check).
   Locked tiles are not buttons: muted, a lock icon and the words (Level 9, Earn Night Owl). Achievements and the XP log are
   divided lists. The tabs are a segmented control and stay in the URL (`?tab=`).
7. Gallery: `src/lib/design-gallery/companion.ts` replaces `awaiting("R4")` with a gallery entry, and there is a page under
   `src/app/design/screens/companion/` for every state the plan lists (loading, storage error, new achievement (one and
   several), every level unlocked, room full, an outdoor background, no XP yet, rename (empty, too long), the longest name
   (24)), and for each of the four tabs. A screen that reads a query parameter cannot have it in a registered route: see
   the handoff §5. Sample helpers go in `src/components/design/companion-samples.ts`. If a state needs Mochi
   mid-celebration, check what `prepare` can reach. A state the store's public actions cannot reach is listed in the
   handoff with the reason; it is not a licence to edit the store.
8. Behaviour unchanged: XP, levels, unlocks, the forgiving streak and what an item needs are the same (nothing under
   `src/lib/rewards/**` or `src/lib/store/**` changes); an equipped item persists across a reload; the rhythm card still
   pluralises correctly.
9. `npm run check:full` green; `npm run design:check` 0 errors; every `design-ok` you add has a real reason and is listed
   in the handoff.
10. Browser journeys (`npm run test:e2e` against a local dev server, all three widths): everything that passes on untouched
   `redesign` still passes. Nine tests already fail there and are not yours: `offline.spec.ts` (2 tests × 3 widths) and
   `sweep: public pages` (× 3). Do not fix, skip or delete them.

YOU OWN: `src/components/companion/**`, `src/components/mochi/**` (the drawing itself stays as it is: point 2),
`src/app/(app)/companion/**`, `src/lib/companion/**`, `tests/companion-*`, `tests/mochi-*`,

DO NOT EDIT: anything lane R0 owns (`src/app/globals.css`, `src/components/ui/**`, `src/components/shell/**`,

"Asks for R0"; it is not invented and R0's files are not edited. Home (R1) and Settings (R5) import Mochi, her mood, the
```
