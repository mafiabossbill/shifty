# Lane R0 — brief

The whole brief for the foundation lane of the redesign (`factory/REDESIGN.md`). A cloud session started with
"read `factory/lanes/R0.md` on the `redesign` branch and do exactly that" needs nothing else.

```
LANE R0 — Foundation: design system, shell and shared parts, a plan for every screen · app SHIFTY (mafiabossbill/shifty)

AGENT: ux-architect. You are this agent for the whole session: read `.claude/agents/ux-architect.md` first and work under
that contract. You are one lane of a larger redesign; do not start other sessions.

START: the default branch `main` is PRODUCTION. Do not base work on it and never open a PR into it. Base your branch on the
integration branch: `git fetch origin redesign`, then make your working branch start exactly at `origin/redesign` (if your
session was given its own branch, keep its name and `git reset --hard origin/redesign` before any work). `npm ci` first. At
the end open a PR with base branch `redesign`. Never merge, force-push to a shared branch, or deploy.

READ FIRST, in this order: `factory/REDESIGN.md` (the plan, decisions R-D1…R-D6, ownership, the marker rule),
`docs/factory/docs/UI_UX_STANDARD.md` (all of it), `docs/factory/checklists/design-review.md`,
`.claude/design-reference/README.md` and the files it lists (the starter's implementation to port), `PRODUCT.md`,
`factory/SCREEN_LANES.md` (how screens get their data), `CLAUDE.md`.

GOAL: Bring the factory's design system into SHIFTY and convert everything shared, so five feature lanes can each redo one
area afterwards without inventing anything. It is a look-only redesign: every feature, route, URL and behaviour stays
(R-D1). Light theme by default with dark as an option (R-D2); no glow, no gradients (R-D3); the action colour is the
system's near-black, violet stays only in the logo mark and in Mochi (R-D5).

ACCEPTANCE:
1. `src/app/globals.css`: the seven-step type scale with Tailwind's own sizes switched off, the three elevations with
   Tailwind's shadows switched off, `--control` (field edge) at 3:1 or more in both themes, one corner policy, light default
   and a dark theme, no gradient or glow. SHIFTY's own type classes (`type-hero`, `type-stat` and the like) are replaced by
   the scale.
2. `cn()` in `src/lib/utils.ts` knows the scale and elevation names (see the reference), with the test from the reference.
3. `scripts/design-check.ts`, `scripts/design-shots.ts`, `tests/design.test.ts` in place; npm scripts `design:check` and
   `design:shots`; `/factory/screens/` ignored by git.
4. `src/components/ui/**` fully converted: no findings and no marker. Buttons by rank (solid, outline, underlined link,
   ghost; red only as the confirm step; no grey-filled variant). `Field` lays out label, hint, error above the control.
   Review `card`, `stat-tile` and `progress-ring` against the standard: a box only around a distinct object; a ring only if
   it answers a question, otherwise a plain figure or bar (say what you decided in the handoff).
5. Shell (`src/components/shell/**`), theme switch, sign-in pages (`src/app/(auth)/**`, `src/components/auth/**`), legal
   pages (reading size, at most about 70 characters a line), `no-access` and error pages converted: no findings, no marker.
6. The gallery at `/design`: development only (a production build answers 404 and the path is not public there; test it),
   with a system page showing type, colour, space, depth, actions, fields and states. Fold the existing
   `src/app/(app)/design` page into it and remove that page from the signed-in area. The registry is one file per area under
   `src/lib/design-gallery/` plus an index; every signed-in route is listed; feature screens are registered as exempt with
   the reason `awaiting redesign lane R<n>`. Provide a gallery shell and a helper that renders a real screen under the store
   with sample data (the demo seed in `src/lib/demo/seed.ts` for a full state, an empty store for the empty state), and
   document how feature lanes use it.
7. The marker rule from `factory/REDESIGN.md`: every file you do not convert that has findings gets
   `// design-ok-file: awaiting redesign lane R<n> (<area>)` in its first lines, with the lane from the ownership table.
   Mochi's drawing files get the permanent reason from R-D4 instead. Then `npm run design:check` reports 0 errors.
8. A screen plan for every signed-in screen in `factory/PRODUCT_BLUEPRINT.md` § Screens (standard §2.1): purpose, who
   arrives and from where, type, primary action (at most one), content ranked 1 · 2 · 3, pattern, states, phone, next step,
   and one line on what must change visually. Write them from what the screen does today. Examples of what a plan settles:
   Home's clock-in is the one solid primary action with no glow; Insights' ring chart becomes bars.
9. `CLAUDE.md` carries the UI rules (take them from the reference `CLAUDE.md`).
10. `npm run check:full` green. Browser specs in `e2e/**` change only where your own copy or selectors changed.

YOU OWN: `src/app/globals.css`, `src/app/layout.tsx`, `src/app/(app)/layout.tsx`, `src/app/(app)/error.tsx`,
`src/app/(app)/design/**` (becomes `src/app/design/**`), `src/app/(auth)/**`, `src/app/(legal)/**`, `src/app/no-access/**`,
`src/components/ui/**`, `src/components/shell/**`, `src/components/theme/**`, `src/components/auth/**`,
`src/components/design/**`, `src/lib/utils.ts`, `src/lib/theme.ts`, `src/lib/public-paths.ts`, `src/lib/design-gallery/**`,
`scripts/design-check.ts`, `scripts/design-shots.ts`, `tests/design.test.ts`, `tests/ui-primitives.test.ts`,
`tests/public-paths.test.ts`, `package.json` (scripts only), `.gitignore`, `CLAUDE.md`, `factory/PRODUCT_BLUEPRINT.md`
§ Screens, `factory/DECISIONS.md`, `factory/handoffs/redesign-r0.md`, one line appended to the Log of `factory/REDESIGN.md`.

DO NOT EDIT: the feature folders (`src/components/home`, `session`, `sync`, `sessions`, `insights`, `companion`, `mochi`,
`settings`, `account`, `pwa`, `workspaces`, and their pages under `src/app/(app)`) beyond two things: the one-line marker,
and mechanical edits needed to keep the build compiling when you rename a class or a variant (no restyling; list them in
the handoff). Never touch `src/lib/store/**`, `src/lib/time/**`, `src/lib/reports/**`, `src/app/api/**`, `supabase/**`,
`public/sw.js`, `docs/factory/**`, `.claude/**`.

MIGRATIONS: none. This environment holds the LIVE database's settings: never run any `db:*` script,
`scripts/factory/release`, or anything that writes to Supabase. The app runs without a backend in device mode; `/?demo=1`
shows generated data.

DESIGN:
- Build only from the system you are installing. Anything the standard leaves open is decided once, in `globals.css` or a
  primitive, and recorded in `factory/DECISIONS.md`.
- Phone layout first. Unconverted feature screens will look wrong on this branch until their lane lands; that is expected.
- Run `npm run design:shots` (Chromium: `E2E_CHROMIUM_PATH`, usually `/opt/pw-browsers/chromium`), OPEN the images in
  `factory/screens/` and look at them: the system page, the shell around one screen, sign-in, a legal page, at 375 and 1280,
  light and dark. Fix what you see and repeat. Reading the code is not a review.

GUARDRAILS THAT APPLY: no new public route in production; no secrets; accessibility AA (text 4.5:1, field edges 3:1) in
both themes.

DONE MEANS:
- `npm run check:full` green (the Stop hook blocks otherwise); `npm run design:check` 0 errors
- `factory/handoffs/redesign-r0.md` written: what changed, every decision, every renamed class or variant with its
  replacement (feature lanes depend on this list), how to add a gallery page, anything you could not finish
- PR into `redesign`, body: what changed, a checklist of what you actually verified with command output, the DESIGN REVIEW
  verdict block from `docs/factory/checklists/design-review.md` naming the gallery pages you looked at, the count of
  `awaiting redesign` markers per lane

FINAL REPORT (≤200 words): branch, PR link, verification, open risks.
```
