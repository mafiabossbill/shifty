# Lane R3 — brief

The whole brief for the Insights lane of the redesign (`factory/REDESIGN.md`). The launch prompt is the block below. It
works as a cloud session (environment `Shifty`, starts from `main`) and as a local session on Bill's Mac in its own git
worktree.

```
LANE R3 — Insights: range dashboard, its charts and the share recap · app SHIFTY (mafiabossbill/shifty)

AGENT: frontend-engineer. You are this agent for the whole session: read `.claude/agents/frontend-engineer.md` first and
work under that contract. You are one lane of a larger redesign. Four other lanes (R1 Home, R2 Sessions, R4 Companion,
R5 Settings) run at the same time on other files. Do not start other sessions.

START: the default branch `main` is PRODUCTION. Never base work on it and never open a PR into it. Your branch must start
from the integration branch `redesign`:
- Cloud session (you began on `main` or on a branch cut from it): `git fetch origin redesign`, keep your branch name and
  `git reset --hard origin/redesign` before any work.
- Local session in its own git worktree, on a branch already cut from `redesign`: `git fetch origin redesign`, then
  `git merge-base --is-ancestor origin/redesign HEAD`. If that fails and you have no commits of your own yet,
  `git reset --hard origin/redesign`.
Either way `factory/handoffs/redesign-r0.md` must exist once you are on it. If it does not, the foundation is not merged
yet: stop and say so. `npm ci` first. At the end open a PR with base branch `redesign`. Never merge, force-push to a shared
branch, or deploy.

ON BILL'S MAC (skip this block in the cloud):
- Work only inside your own worktree folder. Other lanes use other folders. Never switch branches, stash, reset or edit
  anywhere else, the main checkout included.
- There is no `.env` file and none is to be created. The app runs without a backend in device mode; `/?demo=1` shows
  generated data.
- Chromium: `export E2E_CHROMIUM_PATH="$(ls -d ~/Library/Caches/ms-playwright/chromium_headless_shell-*/*/chrome-headless-shell | tail -1)"`,
  or `npx playwright install chromium` if nothing is cached.
- Your ports, because other lanes run servers at the same time: dev server 3013, screenshots 4313.
  `npx next dev -p 3013` · `E2E_BASE_URL=http://localhost:3013 npm run test:e2e` · `npm run design:shots -- --port 4313 --only /design/screens/insights`
- Stop every server you started before you finish.
In the cloud: Chromium is usually `/opt/pw-browsers/chromium`; the default ports are fine.

READ FIRST, in this order: `factory/REDESIGN.md` (the plan, decisions R-D1…R-D6, ownership, the marker rule),
`factory/handoffs/redesign-r0.md` (all of it: §3 renames, §4 the mechanical edits already made in your files, §5 how to add
a gallery page, §9 asks), `factory/PRODUCT_BLUEPRINT.md` § Screens ("Rules every plan shares", then "`/insights` Insights

with one change Bill decided (R-D3): the ring chart goes and plain bars answer its question. Every chart must answer a
question (standard §13). Build the screen from its plan in `factory/PRODUCT_BLUEPRINT.md` § Screens and show every state the
plan lists in the gallery.

ACCEPTANCE:
1. Every file you own that carries `// design-ok-file: awaiting redesign lane R3 (insights)` is converted and the marker is
   removed. Today that is 12 files in `src/components/insights/`: `bars-card`, `chart-kit`, `day-ribbon`, `heatmap-card`,
   `hours-ring`, `insights-controls`, `insights-screen`, `month-calendar`, `patterns`, `session-breakdown`, `share-recap`,
   `summary-cards`. No retired class, variant or prop is left in any file you own (handoff §3; `tests/design.test.ts`
   enforces it once a marker is gone).
2. No primary action: the screen is for reading. Share week / Share recap and Mark this week reviewed are outlines;
   reviewed shows a `success` pill.
3. Must change (from the plan): **Hours in motion goes**. The concentric rings and radial spokes answer what the bars
   already answer. Its total, breaks, days worked and average become the figures above the bars (`StatTile`, no box, net
   worked as `text-display`); its Live pill becomes "Clocked in". Remove the ring component and its file if nothing else
   uses it. Calendar and heatmap tints are steps of grey with the hours written in the cell. The pulsing circle on a
   running band goes.
4. Charts per the shared rules: bars and bands in greys (one darker step for today or the selected mark), the goal as a

   small titles divided by space and lines: no card per chart.
5. The share recap image is redrawn in the light theme (white, near-black, greys). It is an exported picture, so its
   literal colours are a documented exception (`design-ok` with that reason). It still leaves out location unless
   "Include place names" is on.
6. Gallery: `src/lib/design-gallery/insights.ts` replaces `awaiting("R3")` with a gallery entry, and there is a page under
   `src/app/design/screens/insights/` for every state the plan lists (loading, storage error, no sessions at all, nothing
   in this range, a running session in range, the two modes differ, a chart failed, the `?session=` view with its
   not-on-this-device and in-the-trash cases, pay off and no places), across the ranges that change the layout (week,
   month, year), plus the share dialog held open. A screen that reads a query parameter cannot have it in a registered
   route: see the handoff §5. Sample helpers go in `src/components/design/insights-samples.ts`. A state the store's public
   actions cannot reach is listed in the handoff with the reason; it is not a licence to edit the store.
7. Behaviour unchanged: range, date, mode, heat span and `session` stay in the URL; every figure and bar still opens the
   sessions behind it; the numbers are the same numbers (nothing under `src/lib/reports/**` or `src/lib/time/**` changes).
8. `npm run check:full` green; `npm run design:check` 0 errors; every `design-ok` you add has a real reason and is listed
   in the handoff.
9. Browser journeys (`npm run test:e2e` against a local dev server, all three widths): everything that passes on untouched
   `redesign` still passes, sideways scroll on phones included (R0 kept `overflow-hidden` at four call sites when the old
   `hero` card went: do not bring the scroll back). Nine tests already fail there and are not yours: `offline.spec.ts`
   (2 tests × 3 widths) and `sweep: public pages` (× 3). Do not fix, skip or delete them.
```
